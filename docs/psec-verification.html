Why CPU Verification
Don't trust the hash. Reproduce it.
The verifier of last resort
The problem
A marketplace of GPU providers can agree on a hash. But how do you know that hash is the right answer — not just N providers agreeing on the same wrong thing? Trust collapses to whoever the providers are.
The PSEC answer
Take the model weights, the prompt, and the published PSEC reference artifacts. Run the model yourself — on a laptop CPU, no GPU at all, in single-file zero-dependency C. If the CPU produces the same hash as the GPUs, the computation is deterministic and correct. Anyone can do this. The marketplace doesn't need to be trusted.
What this means for the marketplace
Every receipt settled on Galileo and pinned in ENS is independently re-runnable. The CPU verifier is slow (~20 min for 20 tokens) — that's the point. It's the appeal court, not the daily driver. Fast GPU consensus for normal trades; deterministic CPU replay when a buyer wants the strongest possible guarantee.

PSEC v1 · Reference Artifacts
What a PSEC implementation must produce
The published spec for a verifiable inference receipt
Model Weights qwen2.5-14b-instruct-bf16.gguf
Qwen 2.5 14B Instruct BF16 · 14.77B parameters · BF16 (Brain Float 16)
Accumulation Descriptor qwen2.5-14b-accum.bin
Deterministic 32-lane chunked FMA reduction order with butterfly warp reduction and side corrections. Ensures identical floating-point accumulation across all GPU architectures.
Canonical LUTs rsqrt_canonical_even.bin · rsqrt_canonical_odd.bin · exp_canonical_reduced.bin
Precomputed rsqrt and exp values for bit-exact nonlinear operations (RMSNorm, Softmax, SwiGLU). Eliminates hardware-dependent approximations. (96 MB)
RoPE Table rope_canonical.bin
Precomputed rotary position embeddings matching GPU kernel output. Ensures position encoding is identical across implementations.
CPU Verifier dsec-verify.c
Single-file, zero-dependency C implementation. No SIMD, no fast-math. Deterministic by construction. ~20 min for 20 tokens.
PSEC is the open contract. Any prover that produces these artifacts and the canonical output for a given input can join the DeFacts marketplace.
